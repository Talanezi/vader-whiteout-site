# Applications hub · M01

This is a buildless static page. Serve the site repository root, then open
`http://127.0.0.1:4173/apps/`:

```sh
python3 -m http.server 4173 --bind 127.0.0.1
```

The three semantic destination links contain both the complete figure region
and its description. Their original paths are `/scheduler/`,
`/productiondesk/#/`, and `/equipment/`. Both header links return to `/`.
No app bundles, application source, authentication, or deployment files change.

## Artwork and interaction

The original figure sources are in `figures/`. They retain the
`hairline({ name, means, rules, range, tour, mount })` format, so Hairline's
`hairline-create` build, validate, and look tools can inspect them independently.
The objects and gestures were already specified; concept selection was skipped.

- Scheduler: a standing availability instrument with depth, support feet,
  overlapping frame layers, and a common time range. A continuous, bounded
  spring field lifts nearby cells; adjacent cells on the same time range
  coordinate their highlight. Hit testing uses resting projected centres.
- Production Desk: four ruled call sheets, page thickness, grouped fields,
  and a metal clip on a board. Exploded's spring gap and Stack/Riffle's
  distance stagger separate layers, with the top sheet travelling furthest.
- Equipment: an open hard case, fitted compartments, camera with a cylindrical
  lens, two spare lenses, latches, corner protection, hinges, and a handle.
  The lid rotates about its back hinge; contents lift slightly within their
  compartments. Visible grip rings use only front-facing arcs.

`vendor/hairline-kernel.js` is an **unmodified** copy of the skill kernel.
It supplies projection, rounded rings/prisms, spring/tween clocks, fixed
pointer coordinates, shared scheduling, reduced motion, and offscreen sleep.
Its SHA-256 integrity header is retained. The adjacent MIT license must stay
with it. Source: https://github.com/lucasmarkes/hairline at commit
`37d2e78dcb333ab30c3338e28ed4a690364ea014`.

`figure-registry.js` collects the figure declarations. `apps.js` imports the
figures and mounts them without the development bench or tour controls. The
links relay mouse and keyboard focus to the fixed figure plane; SVG cannot
intercept navigation. Touch taps navigate directly. Reduced motion retains the
rest geometry with immediate CSS emphasis. Nothing autoplays.

`apps.css` applies the requested Whiteout palette to Hairline's plate, bright,
edge, medium, and low roles. Opaque plates match the background. Typography
uses the site's Crimson Text/Inter convention with local serif/system fallbacks.
There are no essential CDN assets, package dependencies, or build step.

## Static fallback maintenance

`index.html` includes SVG rest snapshots between `STATIC:<name>` comment
markers. These display before initialization and with JavaScript disabled or
unavailable. A failed mount restores its original SVG.

When changing figure geometry, use the original Hairline skill to build and
validate the figure, inspect its rest/answer/small/theme/extreme screenshots,
then refresh that figure's inline SVG from its mounted rest state. The initial
snapshot was generated by opening this page in Chrome, waiting for the figures
to settle, and copying each `.figure` element's SVG into its matching static
comment pair. Do not capture a hover or keyboard focus pose. Keep static and
interactive artwork synchronized.

## Local verification performed

Chrome browser QA covered 1440×900, 1280×800, 1024×768, 768×1024,
390×844, and 360×800. All three independent Hairline look suites passed:
frame bounds at both intensity extremes, rest/read-out, console cleanliness,
settling, and a measurable pointer response. Their full sheets, small/blind
views, and motion strips were visually inspected.

Integrated QA covered the full figure hit area and title navigation, original
app entry HTTP responses, Production Desk's hash, brand/home links, Tab/Enter,
visible focus and representative figure poses, single-tap touch, reduced motion,
no JavaScript, a missing engine, long content, and native Chrome 200% page zoom. Navigation document
requests were intercepted after the initial entry checks to avoid booting the
other applications or contacting their backends. No application actions ran.

There was no horizontal overflow at the required sizes. All figures recovered
their exact rest geometry, and the animation loop stopped after settling.
Screenshots and machine-readable verification results are review artifacts
outside the site repository. The public Apps page includes no test controls.
